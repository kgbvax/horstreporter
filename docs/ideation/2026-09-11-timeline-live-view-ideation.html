Timeline & Live View — Ranked Directions

Date 2026-09-11 Topic timeline-live-view Focus Timeline & live view Mode repo-grounded Raw 48 ideas → 7 survivors

Grounding Context

Branch ui-stalled-stop-button carries the uncommitted successor to the removed time-travel/replay feature (deleted Sep 2026, commit 53c171c): history.go serves /api/history — per-window gzipped spot bundles from the Postgres archive under hard guards (24h span cap, 50k-spot cap with truncated flag, 120/h per-IP limiter, concurrency gate of 4 → 503, 16-entry/10-min LRU, X-History-Reach header). static/timeline.js is the client playhead machine (1-hour chunk fetches, LRU of 4, prefetch, speeds 60/240/600x, 5-min scrub snap, presets, loop, ?tl=1&t0&t1&spd URL). The toLiveSpot moment contract reshapes past data to live-spot form so the existing Mercator/azimuth render pipeline runs unmodified. static/afterglow.js adds a Mercator-only decay canvas (5-min exponential in data-time). A red stop button (setSubmitMode data-mode contract) marks the live seam.

Pain points verified in the working tree: the scrub bar is a blind 0–1000 range input that fetches a chunk per input event; the client never reads truncated or displays X-History-Reach; syncTimelineURL does replaceState per emitted moment (~24 fps) and URL restore seeks to t1, contradicting info.md's "exact past view" promise; afterglow decays via a hardcoded moved=true plus a 400ms wall-clock window with MOVE_THRESHOLD/FADE_IN_MS declared but unused; azimuth renders moments at fixed alpha 0.8 (no decay); the marker layer and afterglow double-ink the same coordinates; no SSE heartbeat exists (the live loop writes only on spot arrival, safeSend drops silently, favicon never decays — the stall watchdog added in 8eb14e6 was deleted same-day in 8fd80dc); grayline no longer follows the playhead (the removed overlayNowMs was not re-pointed); all analytical surfaces (ActivityByBin chart, band baseline, prop_intel matrix) stay pinned to now during playback; the removed predecessor had step buttons, an editable loop range, a density histogram, and grayline-follows-playhead.

External research found no ham-radio spot tool with trail/afterglow animation (open lane); SUSE Observability's playhead/pause/brush/"Back to Live" pattern and SDR-waterfall "persistence" (decay vs max-hold) are the closest adjacent patterns. HamRBN's shutdown is the cautionary tale: dots-on-map replay alone wasn't sticky — time-resolved conditions were the value.

I1

One-ink alpha contract: decay becomes a property of the spot draw

axis 2 · Afterglow & trail rendering

Lift decay out of the separate afterglow canvas and into the moment contract every renderer already consumes. The playhead-relative ageSeconds each renderer receives becomes the input to one shared alpha policy; "moving" is real playhead velocity (data-time delta per wall-second, tested against the declared MOVE_THRESHOLD) instead of the hardcoded true from app.js:2110 plus a 400ms wall-clock window; the decay constant scales with playback speed so the same visual story plays at 60x and 600x (today a 5-min data-time tau at 600x is a 1.5-second strobe). Both projections consume it — the Mercator hull draw and the azimuth scene loop (currently fixed globalAlpha = 0.8, i.e. time-blind) — and the separate afterglow canvas that double-inks coordinates the marker layer already paints is deleted.

Basis
direct: app.js:2110 — updateAfterglow(spots, playhead, true) (verified); afterglow.js:124 — const moving = (nowMs - lastMoveAt) < 400; with MOVE_THRESHOLD declared at :32 and never referenced; FADE_IN_MS exported and unit-tested but absent from the draw path; azimuth-runtime.js:1849 — ctx.globalAlpha = 0.8; with no per-spot age term; renderers.js:780 — fixed hull opacity 0.9/0.18, so afterglow's "matches the live map's look" claim is numerically false. external: SDR-waterfall persistence vocabulary (decay vs max-hold), analog-scope phosphor.
Rationale
Three verified defects (dead decay trigger, time-blind azimuth, double-ink) share one root cause: decay policy lives in the wrong place. The moment contract was the branch's one load-bearing abstraction decision — this finishes it. Every future time-aware surface (heat layer, KDE field, trend halo) inherits decay for free, and one visual language covers both projections.
Downsides
Touches the render path both projections share — needs the manual wheel-zoom/scrub profile the perf gate can't do (it mocks L); the paused-view parity target ("byte-match the live renderer") needs a deliberate spec decision.

90%

I2

The density/honesty scrub bar

axes 1+3 · Transport · History data

Replace the blind 0–1000 range input with a strip the data paints: per-5-min-bin spot density in the canonical band palette, per-band color mix, chunk-coverage shading (hatched for unfetched), the truncated extent marked, and the X-History-Reach boundary as a hard left edge — three server signals the client already receives and silently drops. Add preview-on-drag (hover renders the hovered moment, release commits) and event ticks: the opening/closing classifier the backend already has (hot_bands.go sustainedRecentBins, the 48-slot baseline) pointed at the scrub rail, so operators scrub to events rather than to times. The removed timetravel shipped the histogram half (/api/replay/histogram); this is its return with honest data behind it.

Basis
direct: timeline.js:557-563 — pause(); seek(snapToScrub(t)) on every input event; timeline.js:538 — the bar's only hint is "Scrub snaps to 5 min"; timeline.js:277-282 — client copies only t0/t1/spots, truncated never read; timeline.js:272-276 — reach stored, renderBar never shows it; history.go:449-453 — the server's comment promises the client can "disable deeper scrubbing honestly instead of misreading an empty map as 'dead bands'"; old timetravel.js:249-262 histogram under the bar. external: SUSE Observability brush/zoom; HamRBN's 7-day time slider as primary navigation.
Rationale
Scrubbing is the feature's primary interaction and currently its least-informed control. A silent failure mode looks like physics: scrub into an unserved window, get an empty moment, conclude the band was dead. The server already pays bytes to tell the truth; the client just never listens. The client also holds per-chunk raw spots and computes nothing from them for the bar.
Downsides
A canvas/SVG strip under the bar adds a second rendered surface to the perf-sensitive bottom bar; event detection needs a decision (client over held chunks vs server endpoint) and a baseline-fetch dependency for ticks.
Confidence
85%
Complexity
Medium
I3axes 4+1 · Live seam · Transport

3. One transport state machine — live is the playhead pinned to the edge. Replace "timeline mode" (SSE torn down by hand, restored from localStorage, full history dump re-received on exit) with one transport — streaming | paused-at-T | timeline-at-T — where live is the playhead pinned to the moving edge and scrubbing is a playhead assignment over buffered data. Keep the SSE connection open under timeline (the soft-pause machinery and its catch-up already exist at app.js:702-721); on exit, re-age in place instead of reconnecting. Add the health channel that makes the whole thing honest: a 15s server heartbeat tick (the live SSE loop's select has no tick case, so a quiet band sends nothing and client-side silence is undecidable — the reason the stall watchdog was added and deleted the same day) plus expectation-relative health (compare observed traffic to the 48-slot baseline). A shared dataNow() clock restores grayline-follows-playhead (the removed overlayNowMs was never re-pointed — replay currently shows the past under today's terminator) and gives the URL a defined write point: only at mode boundaries, never per frame.

Basis
direct: server.go:392-409 — live loop select has only ctx.Done + client.send cases; hub.go:104-112 — safeSend drops silently under backpressure; app.js:702-721 — resumeFromSoftPause() catch-up exists; app.js:2116-2133 — timeline entry closes EventSource and wipes state.liveSpots; no overlayNowMs matches in static/; app.js:2169-2175 — restore seeks tl.t1; static/info.md:33 — "send someone the exact past view" (contradicted). external: SUSE Observability buffered-live pattern with "Back to Live"; DJ slip mode (track keeps turning, muted, under the scratch).
Rationale
The byte-identical toLiveSpot contract already proves the moment path and live path are the same render pipeline — the remaining separation is lifecycle, and that's where all the pain lives (reconnect on exit, dump-suppression flags, favicon that never decays, the deleted watchdog). A server tick is the only signal that can distinguish "quiet band" from "dead stream" — the client cannot, which is why every client-side heuristic has been wrong enough to delete.
Downsides
Largest rework in the set: state machine + wire-protocol addition + seam rewrite; needs a deliberate re-litigation of the stop-button semantics that 8fd80dc settled by deletion. A held-open connection consumes a hub channel per client during timeline (backpressure already absorbed by buffer + burst guard).
Confidence
75%
Complexity
High
I4axis 5 · Analytical value of time

4. Panels ride the playhead. Fix the mixed-time UI: during playback the map shows time T while Band Stats bins an emptied state.liveSpots and the WSPR matrix keeps polling minutes=15 against now. Compute the playhead-relative aggregates client-side from chunk bundles the client already holds — the same 12-bin ActivityByBin shape the server emits, binning the same way band-lab.js already bins live spots by ageSeconds — so "Reports over time" and the band activity picture follow the playhead, labeled with it. Extend the same data to shade absence: where observed fell far below expected-for-that-slot (the 48-slot baseline is a public JSON field), mark the blackout on the strip — "when did propagation break, and for how long" becomes navigable. The WSPR matrix's band×region chips need server-side climatology z-scores and are deliberately deferred to a separate at= work item on the conditions endpoints.

Basis
direct: wspr-matrix.js:319 — params.set('minutes', '15'); (now-anchored, no playhead input); app.js:2111-2112 — moment listener calls updateBandLab(); updateWsprMatrix(); with no playhead argument; band-lab.js:575-594 — client-side binning by ageSeconds already exists; dx_conditions.go — ActivityByBin (12 bins) and BaselineActivityBySlot (48 slots) shapes already defined and the slot series is a public JSON field.
Rationale
HamRBN's lesson: dots-on-map replay alone wasn't sticky — time-resolved conditions were the value. The client already holds 10k spots per chunk (the raw material for every aggregate) and computes nothing; meanwhile the analytics it re-invokes report a different time than the map shows, which quietly teaches users the analytics are decorative. This converts the timeline from a map replay into a replay of the analytical product.
Downsides
Client binning must respect the RBN/WSPR-out-of-baseline rules (source-aware binning is already modeled server-side, so the shape exists); per-frame binning must be amortized (bin once per chunk load, not per frame).
Confidence
80%
Complexity
Medium
I5axes 1+3 · Transport · History data

5. Shuttle scrub: coarse during the drag, full fidelity on release. Borrow the film-NLE proxy workflow: while the thumb is being dragged, render a coarse moment built entirely from data already in the client (decimated cached chunks) and fetch a full-resolution chunk only on release, play, or a dwell >300ms on one position. Scrubbing becomes zero-network; the server stops paying PG connections and gate 503s for a sampling gesture the eye can't read at full fidelity anyway.

Basis
direct: timeline.js:557-563 — pause + seek() per input event, each driving ensurePlayheadBundle() into the server gate (history.go: 4-slot semaphore, 503, client retries 4x, 16-entry LRU, one PG connection per miss, 120/h limiter). reasoned: scrubbing is a sampling gesture — no human perceives per-pixel fidelity at drag speed — so serving it at full fidelity pays scarce PG-connection cost for information the eye can't use. external: offline/proxy conform in film editing; DICOM coarse thumbnails during fast scroll.
Rationale
Removes three structural frictions at once (per-input fetches, gate retries, server LRU thrash) instead of tuning each, and makes deep 24h scrubbing feel local rather than rate-limited — on the prod box where each cache miss holds a connection.
Downsides
Coarse-vs-full fidelity switch must not flash visibly; dwell threshold needs tuning against FT8 cadence.
Confidence
85%
Complexity
Low
I6axis 3 · History data architecture

6. Coarse two-tier history: bins for the whole day, spots for the playhead. Extend /api/history with a coarse tier the way genome browsers ship bigWig next to BAM: one cheap request returning the entire 24h as per-5-min × band bins (count, unique grids, median SNR — a few hundred KB), with full per-spot chunks fetched only for the playhead's neighborhood. The coarse tier powers the density strip (I2), honest reach, and scrubbing; the spot tier stays exactly as it is. The binning pattern exists in-repo twice (ActivityByBin, 15-min cell buckets) — both pinned to "now" only because nobody pointed the accumulator at an arbitrary historical window.

Basis
direct: timeline.js:44-50 — "a 24h span materializes ~240k rows server-side and would blow the 50k bundle cap, hiding all the deep hours the user just asked for"; history.go:477-483 oldest-first truncation the client never surfaces. reasoned: "all raw, any range" fails at the cap and "all coarse" fails the moment view — the two-tier split is the only shape that satisfies both; the aggregation primitive is already in the codebase. external: bigWig/BAM overview-vs-zoom pattern in genomics.
Rationale
Dissolves several pain points at once: the 50k cap becomes harmless (the coarse view is never truncated), the server LRU/PG-connection-per-miss loses its worst case, the unread truncated flag gets an honest surface, and per-IP rate limiting stops fighting legitimate 24h sessions.
Downsides
A new endpoint shape and cache entry on the one new backend endpoint this feature owns; must respect the single-binary and no-per-spot-scoring boundaries (it does — counts and medians are conditions analytics).
Confidence
75%
Complexity
Medium
I7axis 3 · History data architecture

7. Client session ring: the client retains what the stream already sent it. Today the client wipes its chunk cache on every timeline enter and exit and treats Postgres as the primary history source. Flip it: retain every live frame received in a bounded local ring (a QTH-filtered hour is realistically a few thousand spots — history.go's own comment — so a 6h ring is cheap). The default 1h/6h ranges are then served from the session's own accumulation at zero fetch cost; a band/SNR filter change becomes a re-slice of held data instead of an LRU wipe (the bundle already carries band and snr per spot); Postgres is demoted to what it actually is: the path for deep windows, foreign shared URLs, and fresh tabs — best-effort, with depth surfaced (the table already lost everything once).

Basis
direct: timeline.js:41-42 — chunk memory math and BUNDLE_CACHE_MAX = 4; timeline.js:412-419 — "clearing is still the safe, cheap choice on every fresh entry" (the client throws away data it could keep for free); history.go comment on QTH-filtered 24h size. reasoned: session longevity becomes reach — the longer the tab is open, the deeper the personal timeline — independent of the memory/disk-constrained prod box; the PG path's untested status stops being load-bearing for the common case.
Rationale
Dissolves three pain points at once (server LRU thrash, PG connection per miss, per-entry cache wipe) with no wire-format change — the cheapest de-risking of the whole server path.
Downsides
Ring eviction policy needs care on memory; the ring only reaches as far as the session — deep windows still hit the archive path, so the honest-depth surface (I2) stays necessary.
Confidence
85%
Complexity
Low

Recommended Path

Post-ideation stress-testing (three adversarial reviewers against the working tree) endorsed the survivors with corrections. Where a card's text is corrected below, the note here supersedes it:

  1. I7 session ring, narrowed — ring stores received frames keyed by (qth, filter tuple); re-slicing works only for narrowing filter changes (live spots are server-filtered via spotAllowed, so widening or qth changes must fall through to the archive); timeline mode currently closes SSE, so the ring stops growing at enter-time unless the SSE lifecycle changes — claims shrink accordingly. Fold in the dataNow() clock (grayline follows playhead): it is provably independent of both the tick and the state machine (map.js:394 uses Date.now(); no grayline sync on timeline moments today), and every later item inherits the fix.
  2. I3a server heartbeat tick, standalone — third select case in the per-connection live loop, hub fan-out untouched. Hard constraints found: emit as an SSE comment or named event with empty data — an unnamed data: frame would be JSON-parsed into state.liveSpots as a junk spot (no shape validation); horstprop parses every data: line and only accidentally filters the tick today (feed.go:36-38), so a feed test must make zero-PropReports safe by construction; the tick is inert until a client consumer lands, and that consumer must surface tick-silence vs spot-silence in the status line only — never the red=not-playing button semantics settled by 8fd80dc.
  3. I2 honesty scrub bar — needs a small history.go prerequisite: X-History-Reach is emitted only on the no-Postgres fallback path (history.go:457,472) and never on cache hits, so on prod the header never arrives; truncated is near-inert under 1h chunking. Coverage shading must derive from a persistent fetched-window list, not the 4-slot LRU (evicted chunks would render as "covered"), and the strip is honest loaded-vs-unknown, never loaded-vs-empty. Full-24h density stays out of scope until I6.
  4. I5 scrub fetch policy, reframed — coarse-from-cached-chunks inverts in practice: chunks exist only for visited positions and the LRU holds 4 of ~24, so dragged-into-uncached territory must render as "unknown" (I2's vocabulary) rather than as an empty moment. The real value is the dwell/debounce fetch policy.
  5. I1 one-ink alpha contract, kept as top pick but re-shaped — do not delete the afterglow canvas in the first cut: in the default grid-snr style the Mercator layer is aggregated SNR-opacity squares behind a rebuild-gating fingerprint and structurally cannot carry per-spot alpha, so the canvas survives as the carrier of the contract alpha (deletion only in active-area style, later). Define alpha as one continuous function of (data-age, playhead velocity) — velocity carried in the moment payload — not a boolean profile switch; speed-scaled tau as a switch bakes a ~5.8x pause/play pop into the shared contract. Aggregated surfaces (azimuth KDE 1s cache, Mercator squares) decay in steps unless per-frame recompute is explicitly budgeted — accept stepped decay there and document it. Migrate test/afterglow.test.js pinned semantics in the same item; add a timeline-playback perf scenario first (the gate stubs Leaflet and emits no moments, and the moment listener currently renders unthrottled at raf rate).
  6. I4 panels ride the playhead — unchanged.
  7. I6 coarse two-tier — unchanged; unlocks whole-24h density for the strip and makes the 50k cap harmless.
  8. I3b transport state machine — last, as the only High-complexity item; the tick and clock it spawned are already landed.
